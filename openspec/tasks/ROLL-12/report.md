## Noticed, not touched

1. **RLS not enabled (possible security exposure — high priority).**
   - Files: `rollout/supabase-rollout-rls-policies.sql` (policy definitions); `rollout/supabase-rollout-schema.sql` (table definitions).
   - What is wrong: RLS policies exist for `rollout.products` and `rollout.analytics`, but I could not find an `ALTER TABLE ... ENABLE ROW LEVEL SECURITY` statement in the repository for these tables. If it exists only in the Supabase dashboard, this note is void.
   - Possible impact: without RLS enabled, the policy definitions are not enforced, so the schema-scoping fix in T2 is the only line of defence against cross-app data reads.
   - Out of scope: ROLL-12 only scopes the Supabase clients and adds the analytics columns; enabling RLS is a separate ticket for the Architect.

2. **`product_id` nullability mismatch.**
   - Files: `rollout/supabase-rollout-schema.sql:49` (`product_id TEXT REFERENCES ...` — nullable in SQL); `rollout/src/lib/database.types.ts:49` (`product_id: string` — non-null in TypeScript).
   - What is wrong: SQL allows `NULL`; the hand-written type does not.
   - Possible impact: an insert with a missing `product_id` would succeed in the database but violate the type contract; or a type-driven build could reject valid rows.
   - Out of scope: ROLL-12 only adds `source` and `visitor_hash`; `product_id` is left exactly as it is on both sides. No SQL or TypeScript change was made. Separate ticket for the Architect.
