EVIDENCE 1 - the visitor hash formula (generate_user_id)
Source: lib/plausible/ingestion/event.ex:566-595
Proves: user_id = SipHash(salt, user_agent + remote_ip + domain + root_domain + replay_session_id)
  - salt: the rotating salt (current or previous)
  - user_agent: full UA string
  - remote_ip: the visitor IP (after remote_ip.ex header resolution)
  - domain: the site domain being tracked
  - root_domain: the registrable domain (via PublicSuffix), not the hostname
  - replay_session_id: optional session-replay ID (EE only)
Rule: the visitor hash is NOT a pure fingerprint - it includes the SITE DOMAIN,
  so the same visitor on two different Plausible-tracked sites gets two different
  hashes. This is cross-site privacy: sites cannot collude to de-anonymize.
-------------------------------------------------------------------------

EVIDENCE 2 - the salt rotation (the privacy innovation)
Source: lib/plausible/session/salts.ex (full, 96 lines)
Proves: salts rotate every 90 seconds (configurable). The GenServer keeps
  two salts: current and previous. Old salts are deleted after 48 hours.
  On each event, put_salts fetches both; put_user_id hashes with current;
  register_session tries previous_user_id (with previous salt) for grace
  period - if a visitor's salt rotated between events, the previous hash
  still matches for one rotation window.
Rule: salt rotation makes visitor hashes UNLINKABLE across time. An attacker
  who captures today's hashes cannot link them to next week's. This is the
  strongest privacy guarantee short of not storing any identifier.
-------------------------------------------------------------------------

EVIDENCE 5 - remote_ip.ex: the IP resolution priority chain
Source: lib/plausible_web/remote_ip.ex (full, 59 lines)
Proves: IP resolution checks headers in priority order:
  1) x-plausible-ip (Plausible's own header, for proxy setups)
  2) cf-connecting-ip (Cloudflare)
  3) x-forwarded-for (generic proxy)
  4) b-forwarded-for (Bunny CDN)
  5) forwarded (RFC 7239 standard)
  6) conn.remote_ip (fallback to socket IP)
Rule: handle ALL the CDN/proxy headers, not just x-forwarded-for. The order
  matters - a spoofed x-forwarded-for should not override Cloudflare's
  cf-connecting-ip when behind Cloudflare.
-------------------------------------------------------------------------

     2	  @moduledoc """
     3	  Implements the strategy of retrieving client's remote IP
     4	  """

     6	  def get(conn) do
     7	    x_plausible_ip = List.first(Plug.Conn.get_req_header(conn, "x-plausible-ip")) || ""
     8	    cf_connecting_ip = List.first(Plug.Conn.get_req_header(conn, "cf-connecting-ip")) || ""
     9	    x_forwarded_for = List.first(Plug.Conn.get_req_header(conn, "x-forwarded-for")) || ""
    10	    b_forwarded_for = List.first(Plug.Conn.get_req_header(conn, "b-forwarded-for")) || ""
    11	    forwarded = List.first(Plug.Conn.get_req_header(conn, "forwarded")) || ""
    12	
    13	    cond do
    14	      byte_size(x_plausible_ip) > 0 ->
    15	        clean_ip(x_plausible_ip)
    16	
    17	      byte_size(cf_connecting_ip) > 0 ->
    18	        clean_ip(cf_connecting_ip)
    19	
    20	      byte_size(b_forwarded_for) > 0 ->
    21	        parse_forwarded_for(b_forwarded_for)
    22	
    23	      byte_size(x_forwarded_for) > 0 ->
    24	        parse_forwarded_for(x_forwarded_for)
    25	
    26	      byte_size(forwarded) > 0 ->
    27	        Regex.named_captures(~r/for=(?<for>[^;,]+).*$/, forwarded)
    28	        |> Map.get("for")
    29	        # IPv6 addresses are enclosed in quote marks and square brackets: https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Forwarded
    30	        |> String.trim("\"")
    31	        |> clean_ip()
    32	
    33	      true ->
    34	        to_string(:inet_parse.ntoa(conn.remote_ip))
    35	    end
    36	  end

    39	  # Removes surrounding [] of an IPv6 address

    42	    ip =
    43	      case Regex.named_captures(@port_regex, ip_and_port) do

    45	        _ -> ip_and_port
    46	      end

EVIDENCE 6 - put_user_id + register_session (the dual-salt grace window)
Source: lib/plausible/ingestion/event.ex:396-440
Proves: put_user_id generates the hash with salts.current. register_session
  ALSO generates previous_user_id with salts.previous. The persistor tries
  the current first; if no session matches, tries previous. This gives a
  one-rotation (90s) grace window where a visitor whose salt rotated
  between events is still linked to the same session.
Rule: when rotating a hash salt, keep the previous salt valid for one
  rotation period to avoid splitting sessions on rotation boundaries.

EVIDENCE 8 - the tracker event payload (track.js)
Source: tracker/src/track.js (176 lines, head)
Proves: the client-side payload sent to /api/event is intentionally minimal:
  payload.n = event name (e.g. 'pageview')
  payload.u = URL
  payload.r = referrer (document.referrer)
  payload.p = custom props
  payload.h = hostname
NO cookies, NO fingerprinting, NO localStorage on the client. The visitor
  hash is computed SERVER-SIDE from IP + UA + domain. The client sends only
  what the server cannot know (URL, referrer).
Rule: privacy-first analytics = client sends minimal data, server computes
  the identifier from request properties. No client-side cookies.
