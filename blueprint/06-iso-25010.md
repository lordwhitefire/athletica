# 06 — ISO 25010 Quality Double-Check

**Blueprint:** Athletica (FULL MARKETPLACE)
**Mode:** Plan

After the 10 Engine Parts, check against ISO 25010's 9 qualities. If a quality has no answer, that's a gap. Maintainability and Safety don't obviously appear in the Engine Parts — ask about them explicitly.

---

## The 9 qualities

### 1. Functional suitability — does it do what is needed?

**Yes.** The full marketplace: storefront (homepage + catalog + search + product detail with variants + reviews), redirect + click pipeline with geo-routing, three-locks admin auth, full product CRUD + variants + bulk import, media library, live analytics dashboard, affiliate program (signup + trackers + balance + payouts), Amazon dead-link detection + optional Creators API enrichment (cache + availability), i18n. Feature Cards 1–15 cover every function the RE engagements studied.

### 2. Performance efficiency — fast for the resources used?

**Yes.** `getClaims()` not `getUser()`. `waitUntil` for click writes. `next/image` with Sanity domains. Upstash cache for hot link + product records. `<Suspense>` for gallery/carousel. SSE over polling for live dashboards (fewer requests). Monthly partitioning on `analytics`. Mobile LCP target. *(RE-05 NextBase §2.4; RE-01 Dub §2.5)*

### 3. Compatibility — works with other systems?

**Yes.** Standard web (HTTP, REST, JSON-LD, OG, schema.org). Supabase Postgres (standard SQL). Sanity (standard CDN). Amazon Creators API (standard REST, OAuth 2.0). Schema-isolated on shared Supabase. `next-intl` for i18n. No exotic protocols.

### 4. Interaction capability — intended users can operate it easily?

**Yes.** Visitors: single-tap CTA, phone-first, in-app browser tested. Admin: full workspace, one user (the client) + later delegates. Affiliates: self-serve signup + dashboard. Honest states (loading, 404, greyed CTA, empty) throughout. URL search params as filter state (shareable, back-button works). *(RE-07 §2.3–2.4)*

### 5. Reliability — keeps working?

**Yes.** Error-tolerant click writes (redirect survives stats outage). `Promise.allSettled` pipeline. Upstash fails open (1s timeout). Sentry + uptime ping. Supabase daily backups + PITR (Pro). Rollback = redeploy. Grace-window salt rotation (current + previous). Transactional payout flow (no partial state). SSE degrades to polling. *(RE-01 YOURLS §2.2; RE-01 Dub §2.3–2.4; RE-06 §2.2; RE-02 Raider §2.5)*

### 6. Security — data protected from wrong people?

**Yes.** Three independent admin locks. Affiliate ownership-based RLS. SHA-256 hashed tokens. Fail-silent 404 (conceals admin surfaces). `FORCE ROW LEVEL SECURITY` + `(select auth.jwt())` / `(select auth.uid())` wrappers. Service-role isolated. EU IP redaction (GDPR). Neutral auth errors. `rel="nofollow noopener"`. `zod` validation on all inputs. `SECURITY DEFINER` for affiliate membership. *(RE-05 entire; RE-05 NextBase §2.2–2.3; RE-01 Dub §2.4; RE-07 §2.5)*

### 7. Maintainability — can it be changed safely later?

**Yes.** Additive migrations only. `variants` + `categories` + `collections` modeled from day one. `campaign` table built (not deferred). Status transitions in service workflows (side-effects localized). Bulk ops as shared module. Two-phase import (per-row status). Layered action-client. Naming conventions fixed. `tsconfig.json` strict. `rollout/AGENTS.md` read before changes. Documentation: README, `.env.example`, changelog, API docs, admin guide, affiliate guide, this blueprint. *(RE-04 §2.1–2.8; RE-05 NextBase §2.5)*

**One honest gap:** owner ruling is no full test suite (area 17). A change to the click pipeline, publish gate, or payout state machine could break a revenue path with nothing automated to catch it. Mitigation: smoke + critical-path test per phase (named in `03-project-ring.md`), the dead-link detector's redirect-time 4xx signal as a passive monitor, and the append-only balance ledger as a financial audit trail.

### 8. Flexibility — can it be moved or adapted?

**Yes.** Standard stack (Next.js + Supabase + Postgres + Sanity), portable across hosts. Env-var-driven. Schema-isolated (could split to separate Supabase projects). Affiliate ledger + geo-routing built as real subsystems (not deferred). Future seller/submission workflow (RE-04 §2.9) can be added without restructuring — the data shape is ready. Multi-marketplace by design (22 locales seeded).

### 9. Safety — avoids causing harm?

**Yes (for an affiliate marketplace's definition of harm).**

- **Financial harm:** affiliate commissions are an append-only ledger with UNIQUE idempotency; payouts wrapped in a transaction; `minimum_payout` + `payout_term` protect against premature/refund-clawed payouts; reversals supported (Amazon claws back). *(RE-02 Raider §2.5; RE-02 Weferral §2.3)*
- **Compliance harm:** Amazon Associates disclosure present; EU IP redaction (GDPR); no price displayed (Amazon policy); `rel="nofollow noopener"`; affiliate agreement + terms; payout tax docs per jurisdiction. *(locked; RE-01 Dub §2.4; RE-07 §2.5)*
- **Reputational harm:** dead-link detection prevents sending visitors to 404 Amazon pages. Greyed CTA honest about missing data. No mock content or Unsplash fallbacks on real pages. Reviews only from the Creators API when available, hidden otherwise (not fabricated). *(RE-03 §2.7; locked)*
- **Operational harm:** redirect never fails on stats-write outage (uptime > analytics accuracy). Rate-limiter fails open. Payout-pipeline stuck-request alerts. Creators API error-rate alerts. *(RE-01 YOURLS §2.2; RE-01 Dub §2.3)*

---

## Result

All 9 qualities answered. The one honest gap (no full test suite, area 17) is an owner ruling with named mitigations (per-phase smoke tests, passive monitors, append-only audit trail). No quality is left unanswered.
